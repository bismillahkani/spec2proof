# Spec2Proof — submission copy

**Tagline:** Don't just ship a fix. Show the proof.

**Problem:** Product requirements, developer fixes, and test results often drift apart. A “fixed” label rarely shows whether the agreed business rule was tested before and after the change.

**Solution:** Spec2Proof turns a supported refund requirement into ten executable acceptance checks, runs them against buggy Python, explains the two failures, proposes a minimal patch, requires explicit review, and exports reproducible evidence after rerunning the same tests.

**DevDay connection:** An MCP App exposes the workbench through the new sidebar and conversation-panel extension metadata. The complete local demo works without an API key; installation inside ChatGPT requires personal plugin/tunnel setup and is not claimed as completed.

**What to watch:** 8/10 before → two-line diff → approval → 10/10 after. The test hash never changes.

**Impact:** Helps product owners, QA, and developers inspect the same acceptance evidence. A receipt can accompany a future pull request or release review. No quantified productivity or reliability gains are claimed.

**Scope:** A bounded refund-policy compiler with seeded bugs and deterministic repair. General requirements, arbitrary repositories, model-generated code, and production sandboxes are future work.
